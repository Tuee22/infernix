# Infernix Legacy Tracking For Deletion

**Status**: Authoritative source
**Referenced by**: [README.md](README.md), [development_plan_standards.md](development_plan_standards.md)

> **Purpose**: Provide the explicit ledger of obsolete paths, duplicate guidance, and outstanding
> cleanup work in `infernix`.

## Scope
- this ledger tracks implementation placeholders, compatibility shims, duplicate definitions, and
  stale guidance that still exists in the worktree or tracked index
- ordinary UI placeholder copy is not tracked here unless it preserves a fallback behavior or
  masks a live platform failure

## Pending Removal

Every row below names a surface that **still exists** and must be removed. When a removal lands
the row is deleted, not moved: per Section D of
[development_plan_standards.md](development_plan_standards.md) the plan carries no history, and a
surface that no longer exists is not something a reader of this plan needs told about.

| Linux pod-wide memory capacity treated as enforcement of each model's smaller `MemoryGrant` ceiling | Replaced by per-invocation cgroup-v2 enforcement or a compiler-proven one-model-per-pod limit equal to the grant | Phase 4 Sprint 4.32 |

The doctrine and the toolchain-boundary sprint both describe them as the live fail-closed observation and the stronger both-limits form, so they read as engaged behaviour on the supported Apple host. Either give them a supported caller or retire them and the prose that cites them | Phase 6 Sprint 6.46 (consumes Phase 1 Sprint 1.21) |
| `buildMemoryBudgetForPhysicalMib` in `src/Infernix/BuildMemory.hs` and its `Infernix.HostMemory` callers | Derives the toolchain budget from a bare effective-capacity integer that is blind to the inference partition drawn from the same pool, so the two accounts cannot be checked against one claimable quantity. Replaced by a derivation both occupants share | Phase 1 Sprint 1.21; Phase 4 Sprint 4.31 |
| `minHostHeadroomMib` in `src/Infernix/Types.hs` as the sole residual term | A declared constant whose enumerated co-tenants exclude the toolchain, while the toolchain draws on the same pool. It relocates to the shared claimable-pool derivation as the co-tenant headroom term, with the toolchain admitted against the pool rather than against headroom | Phase 4 Sprint 4.31 |
| The build-only `GHCRTS` cap channel at `bootstrap/apple-silicon.sh` and the dependency-building steps of `docker/Dockerfile` | Every repository binary except one test component discards the value by linkage, and an upstream `build-type: Custom` setup program linked without runtime options refuses to start under it rather than being capped — measured on a direct dependency. The caps that bind are the ones passed on the invocation; the environment channel is retained only where a specifically relinked image requires it | Phase 1 Sprint 1.21; Phase 1 Sprint 1.24 |
| The claim that the governed workflow serializes the toolchain account and the inference partition, in `documents/architecture/bounded_host_memory.md` and its three-way root mirror | The aggregate validation command encloses the toolchain-authority stage inside the cluster-owned validation bracket, so the two are claimed within one bracket rather than serialized. Replaced by an exclusive host claim that admits one occupant at a time | Phase 0 Sprint 0.19; Phase 0 Sprint 0.21 |
| The rendered `planAccountToSampledPeakMultiple` as evidence in `src/Infernix/BuildMemory.hs` | The ratio is displayed and never compared, so the Darwin measurement command reports the same success whether the sampled peak is far below the account or above it. Replaced by a checked quantity whose report is not constructible when the peak reaches the account | Phase 1 Sprint 1.21 |
| The token-based detection that forces `unboundedEngineSpawnExemptedFiles` to coincide with `unboundedExecExemptedFiles` in `src/Infernix/Lint/HaskellStyle.hs` | Sprint 6.44 took the exemption set from twelve rows to seven and closed the whole-token gap that had let `withCreateProcess` through. Four of the seven are kernels. The other three — `CLI.hs` (a long-lived host daemon bounded structurally by its terminate-and-wait bracket, plus an operator passthrough whose executable and argv are the operator's own), `HostPrereqs.hs`, and `HostTools.hs` (both pre-manifest, fixed-argv, and running before the manifest a closed command would need exists) — are **recorded scope decisions carrying required deadlines, not pending removals**, so no row here claims them. What remains genuinely open is the detector: both rules match the same `System.Process` tokens on the same lines, so removing a file from the engine set would fire the engine rule on a line that is not an engine spawn. Separating the two gates needs a stronger detector — a per-site intent annotation, or an AST pass resolving what each spawn actually executes, for which the `check-code` realness pass is the precedent — and not a smaller list. | Successor sprint to Phase 6 Sprint 6.44 |
| `reconcileLegacyHarnessBackup` restoring a pre-v2 `.harness-backup` when no harness reservation exists | This one-way migration path predates reservation ownership, so no owner process group or bounded-command activity can be proven. It is restricted to the lifecycle lock and must never be used for a current transaction; remove it after the pre-v2 workspace migration window, when supported workspaces can no longer contain an unreserved backup. | Phase 6 Sprint 6.43 compatibility retirement after the pre-v2 migration window |
| The lazy per-inference model-bootstrap workflow — the `persistent://infernix/system/model.bootstrap.request` topic family + `model.bootstrap.ready.<modelId>` events, `src/Infernix/Bootstrap/Models.hs` coordinator Failover bootstrap subscription, the `modelBootstrapTopic` config field, and the "engine sees uncached model → publishes bootstrap request" hot path. | Replaced by the coordinator's **eager** `warm-model-cache` staging of every model listed in the mounted `infernix.dhall` at cluster-up (a cluster-up barrier). The model set is the mounted config (source of truth); `src/Infernix/Models.hs` is a demo-only generator of that list. The download/upload/`.ready` mechanics are retained; only the per-request trigger is retired (engine lazy path kept as fallback). | Phase 8 Sprint 8.5 |
| The unbounded host toolchain passthrough: `runCommandWithCwdAndEnvRemovingWithPaths` in `src/Infernix/CLI.hs` and its `runCabalCommand` / `runCommand` callers, which spawn `cabal build all`, `cabal test infernix-unit`, `cabal test infernix-integration`, and `cabal test infernix-haskell-style` through a bare `createProcess` carrying no memory ceiling. | Replaced on the repository-owned CLI path by the closed `ToolchainInvocation` vocabulary and `runToolchainCommand`, which consume an opaque authority carrying the observed `BuildMemoryPlan`. The raw lifecycle stays package-internal and `unboundedToolchainSpawnViolations` rejects a new `HostCabal` spawn surface that omits the ceiling, descriptor precheck, closed descriptors, fresh group, masked leader reap, and exceptional cleanup. This is a CLI-plus-lint boundary, not a universal type-system ban on raw `System.Process`; an uncapped run of the retired path reached 109.46 GiB resident on a 124.94 GiB host on 2026-08-03. | Phase 6 Sprint 6.46 (consumes Phase 1 Sprint 1.21) |
| The **memory dimension** of the `src/Infernix/CLI.hs` entry in `unboundedExecExemptedFiles`. | The exemption's recorded rationale is a decision about *deadlines* — bounding an operator's own run with a deadline they did not choose would be a defect — and that reasoning is sound and retained. It never considered memory, which is a property of the operator's own machine derived from its measured physical RAM. Sprint 6.46 adds the memory dimension without touching the deadline decision, so this row retires only the silent waiver of a memory bound, not the exemption itself. | Phase 6 Sprint 6.46 |
| The in-memory whole-deployment `DemoConfig` record: one Haskell record still carrying `coordinatorDaemon`, `webappDaemon`, `engineDaemons`, `enginePools`, `engineMembers`, `requestTopics`, `resultTopic`, `engines`, and `models` for every role at once. | The **wire** half of this row landed with the system/machine contract split: the generated system contract no longer carries the role, the two in-cluster daemon records, the member list, or a top-level model catalog, and the machine contract carries what is true of one box. The Haskell record survives as the decoder's output with those fields *derived*, so every role is still handed fields it must not act on — the disagreement is gone, the over-broad handoff is not. Retiring it means splitting the decoded value by role, which is a consumer-side refactor across routing, launch, publication, and presentation rather than a wire change. | Successor sprint to Phase 8 Sprint 8.11 |
| The member-identity default: an engine with no explicit member name adopting the first entry of the compiled catalog. | Ascending map order makes that the lexicographically smallest member id, and no bootstrap path passes an explicit name — so two machines resolving one identity is the default rather than an edge case, and each then asserts its own physical RAM as the budget for work the other may execute. Nothing detects it: the broker sees two ordinary `Shared` consumers with distinct process-qualified names. Replaced by a required member id and a broker-side claim, because a host-local lock provably cannot cross machines. | Phase 4 Sprint 4.34 |
| The exactly-once claims attached to the model-staging and pool-topic paths, across the standards, four phase documents, `system-components.md`, and four governed docs. | Delivery is at-least-once and is explicitly retained; producer dedup and the `.ready` sentinel collapse duplicates at the effect, which is the honest form the cross-project Pulsar contract already states. Retired as global claims and retained as evidence for their narrower recorded scope. | Phase 0 Sprint 0.20 (doctrine); Phase 6 Sprint 6.47 (gates) |
| The vanilla-JS admin gate in the verbatim-copied `web/src/index.html`: the cookie-driven `<html>.infernix-admin` detector gating `.operator-ribbon`, `#admin-panel`, and the `.summary-item.cluster-summary` cells, plus the `#personal-dashboard` fetch of `GET /api/objects/list`. | Superseded in idiom rather than in function by folding the gate into PureScript state (`AppState.isAdmin` plus `renderAuthGate`), which keeps one rendering path instead of a compiled SPA plus a hand-written detector in the copied HTML shell. The `spago` build lane exists (`web/spago.yaml`, exercised by `infernix test unit`), so this is an accepted deferral rather than blocked work. Enforcement is unaffected either way — the edge `SecurityPolicy` admin `authorization` rule, the backend `withAdminRequest` gate, and the server-side `users/<sub>/` scoping in `handleObjectsList` are the boundary — so the row retires a duplicated presentation path, not a security surface. | Phase 9 Sprints 9.5 and 9.6 |
